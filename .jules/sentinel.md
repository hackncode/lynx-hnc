## 2024-05-24 - Fix Unsafe Eval for Global Scope Resolution
**Vulnerability:** Global scope resolution logic (e.g., in `android-polyfill.js`, `nativeGlobal.ts`) was using `new Function('return this')()` and `eval('this')`. These functions violate Content Security Policy (CSP) headers that restrict `unsafe-eval` and can cause application crashes or provide attack vectors for Cross-Site Scripting (XSS) if they exist within a context where untrusted execution is possible.
**Learning:** Using `eval` or `Function` constructor to access the global scope is considered security theater and introduces real security risks by triggering CSP violations. The codebase uses these patterns in multiple places for determining the correct global object (`globalThis`, `window`, `global`, etc).
**Prevention:** Global object resolution across the codebase must prioritize direct feature detection (`typeof globalThis !== 'undefined' ? globalThis : ...`) and explicitly avoid falling back to `eval('this')` or `new Function('return this')()`. Furthermore, in TypeScript projects like `lynx-runtime-shared` without implicit Node type definitions, `typeof global` requires a `// @ts-ignore` to suppress TS2552 errors without breaking compilation.
