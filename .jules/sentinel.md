## 2024-05-18 - Fix Unsafe Eval in Polyfills
**Vulnerability:** Found multiple instances of `eval('this')` and `new Function('return this')()` used to detect the global object across the codebase (e.g., `nativeGlobal.ts`, `ttConsole.ts`, `android-polyfill.js`, `lynx-promise/src/index.js`). These constructs violate Content Security Policy (CSP) rules against `unsafe-eval`, potentially causing applications to crash in strict environments or exposing the application to XSS risks in certain contexts.
**Learning:** Legacy polyfills and global resolvers often rely on unsafe execution contexts. When fixing these, a direct feature detection fallback chain (`globalThis`, `self`, `window`, `global`, `this`) must be prioritized. If all fail, the fallback `Function('return this')()` must be wrapped in a `try-catch` block returning `{}` to prevent the `unsafe-eval` violation from crashing the entire script while still ensuring the script fails safely. Also, in TypeScript, explicitly typing the IIFE return as `: any` is required to prevent type inference errors.
**Prevention:** Avoid `eval()` and `new Function()` for global object resolution. Adopt a standard, safe fallback chain or rely on standard bundler injections.
