## 2024-10-24 - Fix CSP unsafe-eval in global object resolution
**Vulnerability:** The codebase was using `eval('this')` or `new Function('return this;')()` directly in global scope resolution without proper feature detection fallback mechanisms, which violates Content Security Policy (CSP) `unsafe-eval` restrictions and can cause the application to crash in strict CSP environments.
**Learning:** In polyfills and global resolution modules (like `nativeGlobal.ts` and `android-polyfill.js`), relying on `eval` or `Function` without checking standard global object references first is a significant risk in modern environments that enforce strict CSP. It also prevents the code from running successfully in edge/worker environments where standard globals might differ. Using an empty object fallback when `Function('return this')()` fails prevents crash propagation but requires caution to avoid modifying real global scope.
**Prevention:** Always prioritize direct feature detection for global objects (`globalThis`, `self`, `window`, `global`, `this`) in that order. Only use `Function('return this')()` wrapped in a `try/catch` block as a last resort fallback, returning an empty object (`{}`) if execution is blocked by CSP, to gracefully degrade functionality instead of crashing the execution thread.
