## 2024-04-19 - [CWE-338] Insecure Randomness in UUID Generation
**Vulnerability:** The `guid()` utility in `js_libraries/lynx-runtime-shared/src/utils.ts` relied entirely on `Math.random()` to generate UUIDs. `Math.random()` is not a cryptographically secure pseudo-random number generator (CSPRNG), leading to a high risk of predictable UUIDs and collisions, which can be exploited for tracking or bypassing identifiers.
**Learning:** In environments with varying levels of Web API support (like Lynx or older JS runtimes), relying on `Math.random()` is a common but dangerous fallback for UUIDs. To safely support these environments without risking security when modern APIs are available, we must aggressively prioritize direct feature detection of secure APIs (`crypto.randomUUID()` or `crypto.getRandomValues()`) before falling back.
**Prevention:** Always use cryptographically secure methods like `crypto.randomUUID()` or `crypto.getRandomValues()` for generating sensitive identifiers or tokens. When writing code for multiple runtimes where `crypto` might not be guaranteed, implement a progressive enhancement strategy using direct feature detection (e.g., `typeof crypto !== 'undefined'`), but never default to `Math.random()` as the primary source of entropy for security-sensitive operations. Additionally, pre-allocate byte arrays when using `crypto.getRandomValues()` inside loops (like `replace`) to avoid performance bottlenecks.
