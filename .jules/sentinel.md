## 2024-05-24 - [CRITICAL/HIGH] Fix Weak Random Number Generation in `guid()`

**Vulnerability:** The `guid()` function in `js_libraries/lynx-runtime-shared/src/utils.ts` uses `Math.random()` to generate UUIDs. This is insecure as `Math.random()` is not a cryptographically secure pseudo-random number generator (CSPRNG), making the generated UUIDs predictable and susceptible to collisions.
**Learning:** In environments where UUIDs are generated for tracking, session handling, or uniqueness constraints, relying on predictable PRNGs like `Math.random()` compromises security. It's a common oversight to fallback to standard random functions instead of checking for and using a CSPRNG available in modern environments (like `crypto.randomUUID` or `crypto.getRandomValues`). Additionally, when using `getRandomValues` in a loop, pre-allocating an array for all needed values is more efficient than allocating inside the loop.
**Prevention:** Always use cryptographically secure random number generators (CSPRNG) when creating sensitive identifiers. Implement a feature-detection fallback mechanism: try `crypto.randomUUID()`, then `crypto.getRandomValues()`, and only use `Math.random()` as a last resort in constrained environments lacking cryptographic APIs. Avoid ES2017+ string methods like `padStart` to ensure compatibility.
