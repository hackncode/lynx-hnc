## 2024-05-18 - Prevent CSP unsafe-eval Crashes in Global Object Resolution
**Vulnerability:** The codebase was using `eval('this')` and `new Function('return this;')()` to reliably obtain the global execution context across different JavaScript environments (Node.js, Browser, Lynx runtime). This approach violates standard Content Security Policy (CSP) configurations that restrict `'unsafe-eval'`, causing unexpected crashes or blocked execution when the code runs in restricted environments.
**Learning:** While `eval('this')` is a known legacy pattern for getting the global object (especially before `globalThis` was widely supported), it creates an unnecessary security risk and CSP incompatibility. It's much safer to directly check for the existence of known global objects.
**Prevention:** To prevent CSP 'unsafe-eval' crashes, global object resolution across the codebase (e.g., in `nativeGlobal.ts`, `ttConsole.ts`, `android-polyfill.js`) must prioritize direct feature detection (`globalThis`, `self`, `window`, `global`, `this`) and avoid falling back to `eval('this')` or `new Function('return this')()`. Note: when using `global` in TypeScript packages lacking explicit Node type definitions, use `/* @ts-ignore */` above the variable to prevent TS2552 errors.
