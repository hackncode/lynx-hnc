## 2025-01-20 - Prevent CSP unsafe-eval in global object resolution
**Vulnerability:** Use of `eval('this')` and `new Function('return this')()` to resolve the global object bypasses Content Security Policy (CSP), creating a risk of runtime errors in restricted environments.
**Learning:** Resolving the global object safely requires prioritizing standard feature detection (`globalThis`, `self`, `window`, `global`, `this`) before falling back to a dynamically constructed function wrapped in a try/catch. When using `typeof global`, TypeScript may throw TS2552 errors if node types are absent, requiring `// @ts-ignore`. In polyfills, using the variable name `_globalThis` avoids shadowing `globalThis` during internal feature detection. Returning `{}` as a last-resort fallback safely handles cases where dynamic evaluation is completely blocked, even though it doesn't represent the true global scope.
**Prevention:** Always use a standardized, feature-detection based `getGlobal()` utility or polyfill rather than direct `eval()` or `new Function()` execution when attempting to access the global context.
