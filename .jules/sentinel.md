## 2024-05-18 - Improve Random Number Generation for GUIDs
**Vulnerability:** Weak random number generation using `Math.random()` in `guid()` generation, posing a potential predictability risk in environments where UUID collisions or sequence prediction might impact logic. Additionally, improper integration of `crypto` risks CSP eval errors or performance bottlenecks (when allocating small arrays repeatedly).
**Learning:** `js_libraries/lynx-runtime-shared` defines a global object but security-critical APIs like `crypto` should use direct feature detection (`typeof crypto !== 'undefined'`) to avoid CSP eval issues. Furthermore, when falling back to `crypto.getRandomValues()`, allocating a single byte array beforehand (e.g., `new Uint8Array(16)`) is critical to avoid significant performance bottlenecks, and string methods like `padStart` must be avoided to maintain ES2016 compatibility.
**Prevention:** Always prioritize established, hardware-backed crypto methods (`crypto.randomUUID()`) when generating UUIDs. Use direct feature detection instead of resolving globals manually, allocate full-sized entropy buffers instead of iterative single-byte allocations, and adhere to the project's specific TS target restrictions (ES2016).
