## 2025-02-21 - Secure UUID Generation and Crypto Fallback Performance
**Vulnerability:** Weak random number generation in `guid()` used `Math.random()` to generate UUIDs. This lack of cryptographic security makes generated values predictable, which could be exploited if they are used as sensitive identifiers, tokens, or cryptographic keys.
**Learning:** The previous implementation avoided standard UUID generation techniques. The environment supports `typeof crypto !== 'undefined'` but due to evaluation risks associated with fallback checks like `nativeGlobal` (which might rely on `unsafe-eval`), direct feature detection should be used instead. Additionally, when using `crypto.getRandomValues()` as a fallback in a character replacement loop, allocating an array per iteration introduces severe performance bottlenecks compared to pre-allocating a single byte array of the required entropy (31 bytes).
**Prevention:** Always use cryptographically secure random number generators (e.g. `crypto.randomUUID()` or `crypto.getRandomValues()`) for identifiers. Prioritize direct feature detection for security APIs and optimize cryptographic loops by pre-allocating random byte buffers to avoid performance degradation.
