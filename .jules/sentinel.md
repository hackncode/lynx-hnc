## 2024-05-18 - [CSP Violation Prevention & Insecure RNG Mitigation]
**Vulnerability:** Code in `android-polyfill.js` and `nativeGlobal.ts` utilized `eval` or `Function` to resolve the global object, and `utils.ts` utilized `Math.random()` for UUID generation.
**Learning:** These practices pose risks in environments with strict Content Security Policies (CSP) which forbid `unsafe-eval`, leading to runtime crashes. Additionally, using `Math.random` is an insecure source of entropy for GUID/UUID generation. We can securely resolve globals using standard fallbacks (`globalThis`, `self`, `window`) and generate random numbers using `crypto.randomUUID()` and `crypto.getRandomValues()`.
**Prevention:** Avoid `eval` and `new Function` for environment resolution unless safely wrapped in a fallback try/catch that swallows errors. Always utilize cryptographic RNG functions like `crypto.randomUUID()` when generating unique identifiers, gracefully falling back to legacy implementations.
